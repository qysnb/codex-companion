# 0.5.0：本地优先与低流量额度查询

## 原因与修复

旧版本启动预取、每分钟刷新、隐藏后继续查询，并在空闲10秒后释放完整Codex App Server，导致下一周期重复初始化。正常运行的代理计量在240秒中观测到57.4MB，这些字节来自查询子进程，不能等同于小份额度JSON；尚未解密HTTPS逐项定位内部路径。

- 默认改为“本地缓存（仅手动联网）”，旧设置缺少新字段时也迁移到本地。启动、普通点击、闲聊、隐藏、重置期限和失败重试均不能自行联网。
- 明确点击“联网刷新额度”或调用插件refresh-quota才读一轮真实账户和额度。缓存只在内存中保留，重启后首次需要手动读取，不复制登录凭据或跨账户复用未校验缓存。
- 可选“按需联网”：点击额度页时才可能读取，成功和失败都遵守至少15分钟的尝试预算。无后台定时或自动失败重试。
- 原后台周期读取改为显式“自动联网”选项；新设置的自动间隔默认900秒，原间隔偏好保留，只有明确开启自动模式才生效。
- 切回本地会取消尚在执行的自动读取，不取消用户明确手动读取；取消不会启动失败重试，新的有效推送不会被旧请求覆盖，取消收尾时立即手动刷新不会丢失。
- 独立查询进程临时关闭插件、远程插件、模型发现、宿主技能发现、MCP和analytics，仅覆盖自建进程，不更改Codex全局配置。
- 重置提醒仍只在真实读取观察同账户0%→100%后触发。本地模式不实时联网监测，也不根据倒计时假造100%。

## 已验证

完整控制台测试通过，新增网络策略覆盖默认迁移、零连接、并发合并、重试/通知/重置门控、按需限频、策略取消、推送竞态和取消后的手动读取。现有84组角色/语言/尺寸布局、24组额度/配色/列对齐、9组提醒及12组气泡时长场景通过，真实5秒自动关闭检查正常。

精简参数的一次真实账户及双窗口查询成功，代理计量595,376字节（约0.595MB），旧查询进程样本为6.5–20.3MB。组合参数样本表明附带通信大幅降低，但不是固定保证或对单个开关的独立归因。当前实测CLI为0.166.0-alpha.5.1；不支持相应开关的旧CLI不会静默回退到高流量启动，应更新Codex，人物本地功能仍可使用。

安装后的自然流量验收结果将记录在发布说明中。计量使用按桌宠子进程PID和TCP源端口归属的代理连接计数，不是运营商全部出口字节。
